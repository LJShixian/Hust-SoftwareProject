# mycc 范围说明（CR-SCOPE-001）

版本：1.0　日期：2026-10-26　实施版本：mycc 0.3.0

**产品目标：输入一个受限 C 程序及可用指令集合，输出 GNU 格式的 RISC-V 汇编，并提供源码诊断和指令选择说明；汇编通过外部工具链验证。**

本说明在程序调整前形成。依据为用户确认的范围收敛要求；0.2.0 的 CPU21 适配保留为外部集成示例，原 Git 提交 `3dd6451`、需求修订及验收证据保留。

## 1. 软件的主流程

```text
受限 C + ISA 配置 → mycc 编译器 → GNU RISC-V .s + 诊断/Lowering 报告
                                      ↓ 可选外部验证
                             GNU 汇编/链接 → 仿真或 FPGA
```

第一阶段只维护 GNU 汇编输出。RARS 格式兼容暂缓；现有 .s 不宣称可直接交给 RARS。原扫雷继续由其既有 GCC 工具链构建，不作为 mycc 必须原样编译通过的输入。

## 2. 范围边界

| 层次 | 本阶段范围 |
|---|---|
| 编译核心 | 词法、语法、作用域/类型检查、ILP32 调用约定、栈帧、代码生成、ISA 校验、软件乘除法/移位回退、确定性诊断与报告 |
| 主界面 | 源码编辑、ISA 预设/组选择、编译/取消、汇编及 Token/AST/IR/Lowering 查看、导出与诊断定位 |
| 编译输出约定 | GNU 汇编；外部函数/软件辅助函数由运行时提供。生成 .s 不等于独立可执行文件 |
| 外部适配 | 启动入口、最终内存地址、链接布局、MMIO、VGA 字形、ROM 导出、CPU21 栈故障策略、RTL 集成验证，集中在 adapters/cpu21 及外部工具中 |
| 开发验证 | 纯 Python 测试、真实汇编/链接、ISA 组合、可选 QEMU/GCC 对照、显式 CPU21 RTL 验证；不作为正常编辑/编译的前置条件 |
| 暂缓 | 完整扫雷、unsigned/volatile/预处理/内联汇编/ISR 语言支持、RARS 后端、自动下载 FPGA、调试器和更多板卡 |

已支持的 int/int*/一维数组、函数、控制流和运算符继续保留。本次不通过删语言功能来缩小范围。

## 3. 默认行为与接口

- `python -m mycc file.c -o file.s` 默认 generic 编译环境和 PF-01，专注于生成汇编。
- ISA 是编译器输入，GUI 中全部已有合法预设和组可选；CPU21 仅为一份参考 ISA 预设，选择它不会自动启用板卡启动、栈检查或 VGA。
- 保留 `--target cpu21` 作为显式外部适配兼容入口；其配置和策略由适配层注入，编译核心不直接了解 CPU21 的外设、固定容量或板卡地址。
- GUI 主流程不启动构建器、QEMU 或 FPGA 进程，不显示 MMIO 地址。可选外部工具以帮助说明提供命令。
- 历史板卡 GUI 设置保留在迁移后的 legacy 字段，主界面不再编辑它们；新配置格式明确版本号。
- 外部构建必须显式选择环境：`tools.build --target cpu21` 生成板卡固件，`--qemu` 生成 QEMU 程序。默认通用构建不冒充实际板卡适配。
- FPGA 工程保持只读；所有生成物写本软件输出目录。

## 4. 三项核心验收

| 编号 | 演示与判据 |
|---|---|
| SC-CORE-01 | 一个含函数/循环/算术的 C 程序生成 GNU 汇编，真实 GNU 汇编/链接成功；有执行环境时验证预期结果 |
| SC-CORE-02 | 同一源码在启用/禁用 mul 等配置下选择不同实现，Lowering 说明原因；外部 CPU21 验证或 QEMU 检查行为一致 |
| SC-CORE-03 | 故意缺分号、使用未声明变量或非法 ISA 时，给出源码位置/诊断或配置建议，失败不覆盖之前成功输出 |

正常编译不能依赖 PySide6、RISC-V GNU 工具、QEMU、Vivado 或外部 FPGA 目录。外部执行验证缺工具时必须报告缺失，不能被描述为执行通过。

## 5. 实施顺序与留痕

1. 先保存本说明为独立 Git 检查点，再修改程序。
2. 恢复 CLI/GUI 的编译器默认行为，移出主界面的硬件控制和运行功能。
3. 把 CPU21 资产、固定硬件事实及目标策略移入适配目录；保持现有板卡验证入口可用。
4. 同步 SRS v1.4、SDD v1.3 修订，说明对 CR-CPU21-001 的默认行为覆盖关系；不删除历史证据。
5. 验证核心演示、GUI 往返及可选 CPU21 回归，保存结果并提交。

本次属于范围和模块职责调整。原 0.2.0 的硬件执行证据保留为历史；0.3.0 的验证结果单独记录，仿真与物理上板保持区分。
