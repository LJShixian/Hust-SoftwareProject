# 实现与验证记录

实现基线：SRS-MYCC-001 v1.2、SDD-MYCC-001 v1.1。日期：2026-10-26。

## 对基线的明确补充

| 编号 | 问题 | 实现选择 |
|---|---|---|
| DC-07 | PF-04 写为 31，但 26 + xor 1 + cmpbr 4 + auipc 1 = 32；PF-07 写为 36，但 26 + 1 + 2 + 1 + 4 + 4 + 1 = 39 | 以指令集合定义为准，不删减任一组；对应测试断言 32、39。原始文档保留。 |
| DC-08 | MMIO 地址与 VGA 单元格式未给出，无法声称已对接真实板卡 | 用户确认改为软件配置地址。提供 GUI 三个输入项、JSON 板卡配置、构建参数和链接符号；示例地址为占位值。VGA 暂用 80×25 个 32 位字符单元。 |
| DC-09 | MV-ISA 只有 9 指令，但常见软件回退仍依赖 and/shift/sltu | 增加指令级保守展开：保存 caller-saved 寄存器，调用只含 MV-ISA 的位运算、比较、移位及字节存储辅助函数。GNU 汇编与白名单检查覆盖该路径。 |
| DC-10 | 软件运行时的十进制/十六进制输出容易与编译器的语义修复漂移 | I/O 输出函数写在受限 C 中，由相同编译器/profile 编译；启动、MMIO、算术和内存辅助函数手写汇编。不是全部手写的 I/O，后续如课程要求应转为经过核对的手写汇编。 |

## 验证范围

当前本机：Windows、Python 3.12.7、PySide6 6.8.3、xPack RISC-V GNU 15.2。使用 `check.cmd` 运行。

- 88 项测试通过；1 项 QEMU 执行矩阵因工具缺失跳过。
- 54 组合并行实际汇编、链接、反汇编检查；另验证无 lui+无变量移位的裸机固件、最小 9 指令代码生成和运行时汇编。
- narrow/wide 负例验证 lint 对 profile 敏感；只允许独立 QEMU 测试适配层中的指定 ecall。
- MMIO 修改后检查 ELF 符号表和固件字节，确认地址确实进入产物。
- 语句恢复与 20 条错误上限、失败不覆盖输出、非法 UTF-8、作用域和类型检查、短路代码路径、自增左值地址只计算一次、ABI 参数和帧布局、配置损坏回退、GUI offscreen 编译回路均有测试。
- coverage.py 采集语句与分支；`tools.check` 对 core ≥80%/分支 ≥60%，codegen/sema/isa 各 ≥90% 语句，CLI ≥70%，有 PySide6 时 GUI ≥60% 设硬门槛。
- 静态检查执行核心导入 DAG、第三方依赖白名单、核心零文件 I/O、GUI 模型零 Qt、语义层不依赖 ISA、7 模块上限。

**不可推断为已验证的内容**：真实目标执行结果、运行时算术边界的机器执行、三环境 CI 结果、GCC stdout 对照、板卡 MMIO 协议、Logisim 导入以及性能/内存/公开 API docstring 比例等量化验收项。测试中的数值语义断言验证 Python 语义函数；不替代目标侧运行。`--full` 要求 QEMU/GCC，防止将工具缺失视作完整验收。

## 当前边界与后续验收

1. 在有 `qemu-riscv32` 的 Linux/WSL 执行 `python -m tools.check --full`，验证 54 组合的预期 stdout/退出码和 GCC 对照。
2. 从实际 CPU 导出 `hw_caps.json`，填写 MMIO、确认 VGA 格式与内存布局后构建并上板。
3. 对照原始 AC-01..AC-13 逐项补充课程验收证据。本实现不把测试通过数量等同于完整需求覆盖率。
4. P1/P2 中 char、switch、?:、do-while 按 SDD 明确延期；不支持的语言特性会拒绝。

最小 9 指令展开以正确性为先，体积与速度明显差于标准 profile；较大程序可能超过板载 32 KiB IMEM。链接器会拒绝溢出。正式推荐使用与硬件一致的 PF-01 或其经过确认的变体。
