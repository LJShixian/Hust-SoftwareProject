## 1. 背景与目标

### 1.1 背景

**BG-01｜硬件侧现状**
项目已实现一台自研 RISC-V CPU（Logisim 单周期原型 + 五段流水线版本，正在迁移至 FPGA/Verilog）。已实现指令集为 RV32I 的一个真子集，另含部分 RV32M（仅 `DIVU`/`REMU`）以及一条自定义的 `URET`。已具备数据前递的流水线冒险处理，单周期版本已实现三级嵌套中断（软件栈保存现场 + 独立优先级栈）。

**BG-02｜软件侧现状**
目前所有上机程序均为手写汇编。手写汇编存在三个具体问题：
1. 无法表达稍复杂的算法（递归、数组、指针）而不产生大量易错代码；
2. 手写过程中误用 CPU 未实现的指令（如 `lui`、`lb`）不会在汇编阶段报错，只会在运行期表现为"程序跑飞"，调试成本极高；
3. 演示说服力有限——"一段 C 代码在自己的 CPU 上运行"与"一段手写汇编在运行"是两个量级的技术展示。

**BG-03｜课程要求**
本项目同时作为软件工程课程设计交付物。课程要求覆盖：需求分析、设计、实现、测试、文档、验收演示，并对需求文档的**正确性、完备性、无歧义性、可验证性、优先级合理性、可追溯性**评分。

**BG-04｜既有探索结论**
此前评估过的替代方案及其结论：
- 直接使用 GCC（`-march=rv32im`）：GCC 会使用 RV32IM 全集中任何指令，无法按"我的 CPU 支持的子集"做减法；只能通过源码规避 + 后处理，需求边界不可控。
- 使用表驱动汇编器（customasm 类）：解决"拒绝非子集指令"，但不解决"从 C 生成代码"。
- 修改 binutils/LLVM 增加自定义指令：成本高，且与课程设计目标（编译器实现）不匹配。

结论：**自研编译器是唯一能同时把"语言语义"与"目标 ISA 子集边界"两个约束握在手里的方案。**

**BG-05｜硬件侧的能力演进**
硬件实现是**渐进**的：四条待补指令（`lui`/`sll`/`srl`/`sra`）的完成时间不确定；乘法器与除法器属于可选投入；若后续为性能或功能补做 `mul`、`div`、`rem`、`lb`/`lbu`，编译器应当**能够直接利用**，而不需要修改编译器源码。同时，硬件能力在**仿真（Logisim）、FPGA、以及未来可能的变体**之间并不一致。因此"目标 ISA 是一个编译期可配置的集合"这一需求来自硬件侧的真实约束，而非功能堆砌。

**BG-06｜现有交互方式的不足**
命令行界面在以下三类真实使用中出现摩擦：
1. **调试回路过长**：修改 C 源码 → 手工敲编译命令 → 手工敲汇编命令 → 手工加载/启动 → 观察输出，一个"改一行看结果"的回合需要 4~5 条命令，而这个回合在游戏开发期每天发生上百次；
2. **指令集裁剪的表达力不足**：以 `--no-lui` 这类开关表达 ISA 裁剪，开关数量随可选组线性增长，且**无法表达"只启用 `div` 不启用 `mul`"这类组合**；
3. **诊断定位靠人工**：命令行诊断需要人工数行号，而"源码 → 汇编 → 运行结果"三段式在调试期反复发生。

**BG-07｜技术栈约束的现实压力**
`CN-01`（仅标准库）来自"最短实现路径"的工程判断，而非不可协商的外部限制。图形界面若坚持纯标准库（Tkinter），代价是：无现成语法高亮 API、行号栏与错误标记需自行实现、CJK 字体与高 DPI 在 Linux 上表现不稳定、无原生文件对话框的组合问题。而 `BG-06` 第 1 条（调试回路）与第 3 条（诊断定位）恰恰高度依赖编辑器的成熟度。**因此本项目在图形界面上做一次显式取舍：放弃 Tkinter 的"零依赖"，换取 Qt 的原生控件能力，并把代价（依赖白名单、安装步骤、离线可用性）写成可验证的需求与约束，而不是含糊带过。**

### 1.2 问题陈述

需要一个工具，把一份用受限 C 语言写的源程序，翻译成**只包含目标 CPU 当前所实现指令**的 RISC-V 汇编，并保证该汇编可被标准工具链组装、链接、加载到目标 CPU 上运行；同时在源程序超出该受限语言范围、或所选指令集组合无法表达某程序时，给出定位准确、可操作的诊断信息。

工具需提供两种人机界面：**命令行界面（权威、可脚本化、可复现）与图形工作台（面向单文件 C 开发日常回路：编辑 → 编译 → 诊断跳转 → 汇编预览 → 运行观察）**，二者共享同一编译内核，行为一致。

### 1.5 术语表

| 术语 | 定义 |
|---|---|
| **SRS** | 软件需求规格说明（本文档） |
| **C 子集 / 受限 C** | 附录 A 文法所定义的 C 语言真子集 |
| **目标 ISA** | 编译器**本次编译**可生成的机器指令集合，由 profile 派生，见 `IF-06` |
| **profile（指令集配置）** | 一份声明"目标 CPU 支持哪些指令"的配置，可为内置（`PF-xx`）或用户提供的 JSON 文件（`IF-07`） |
| **MV-ISA（最小可行 ISA）** | 9 条无 lowering 回退、profile 必须包含的指令，见 `IF-06(a)` |
| **可选指令组（EX）** | 可独立启停的指令集合，启用后改变 codegen 选择，见 `IF-06(c)` |
| **lowering（降级展开）** | 把一条抽象操作展开为目标 ISA 中的等价指令序列的过程 |
| **能力守卫（capability guard）** | lowering 规则的前置条件，形如"`mul` ∈ 目标 ISA" |
| **lowering 表** | 抽象操作 → 有序的（守卫, 展开, 原因）列表；codegen 选取首个守卫成立的项（`D-07`） |
| **RV32I / RV32M** | RISC-V 32 位基础整数指令集 / 乘除法扩展 |
| **ABI / ILP32** | 调用约定：`int`、指针均为 32 位；参数 `a0-a7`、返回 `a0`、返回地址 `ra`、栈指针 `sp`、帧指针 `s0` |
| **MMIO** | 内存映射 I/O；本项目的输出通道 |
| **运行时库（runtime）** | 手写汇编，提供 `_start`、输出函数与软件乘除法 |
| **ICE** | 编译器内部错误（Internal Compiler Error） |
| **助记符白名单 lint** | 对 `objdump -d` 输出逐条比对各指令助记符是否在**选定 profile 派生集**内的检查脚本 |
| **基准程序（benchmark）** | 附录 B 定义的 8 个固定验证程序 |
| **强度削减** | 把昂贵运算改写为等价廉价运算，如乘以 2 的幂常量改写为移位 |
| **core（内核）** | 不含任何 I/O 与界面代码的编译逻辑：`lexer`/`parser`/`types`/`sema`/`codegen`/`isa`/`driver` |
| **front-end（前端）** | 仅负责 I/O 与交互的薄层：`cli`、`gui` |
| **工作台（workbench）** | `gui` 的对外形象：单文件 C 的"编辑→编译→诊断→汇编→运行"单窗口回路 |
| **offscreen 平台** | Qt 的 `QT_QPA_PLATFORM=offscreen` 后端：无显示服务器时创建控件树但不显示，用于自动化测试（`AC-13`） |
| **DoD** | 定义完成（Definition of Done），见 §8.2 |

| RO-05 | **教学演示观众**（同学、答辩旁听者） | **仅工作台**：只读观察，不接触命令行 | 演示时段 | 看懂"这一行 C 变成了这几条汇编、以及为什么" |
| **RO-06** | **验收机的系统管理员 / 环境准备者**（通常是本人，但在验收现场是"正在装环境的那个人"） | `README` 的环境准备章节 + `requirements.txt` + 可选离线 wheel | 每个新环境 1 次 | **能在断网或受限网络下把 GUI 跑起来**；若失败，能立刻退回纯 CLI 完成验收（`NFR-506`、`FM-17`） |

> **RO-04 是"接口型用户"，其需求以 `IF-03`~`IF-07` 形式给出。它是本项目中约束最强、最不容错的用户。**
> **RO-06 是 v1.2 因引入第三方依赖而新增的角色**：只要引入 PySide6，"装不上环境"就成为一个必须被显式管理的用户诉求，而不是"运气问题"。

## 3. 假设、约束与依赖

### 3.1 假设（每条附依据）

| 编号 | 假设 | 依据 |
|---|---|---|
| AS-01 | 目标 CPU 已支持：`add sub and or slt sltu addi andi ori xori slti slli srli srai lw sw sb beq bne blt jal jalr` | BG-01 中已实现指令集清单 |
| AS-02 | 可在设计周期内为 CPU 增加 `lui`、`sll`、`srl`、`sra` 四条指令 | 四条均为已有数据通路的小改动：`lui` 复用已有的 U 型立即数生成器（与 `JAL` 共用），不经过 ALU；`sll/srl/sra` 复用已有的桶形移位器，仅将移位量来源由立即数字段改为 `rs2` |
| AS-03 | 目标平台内存足以容纳运行时库、基准程序与游戏 | 内存映射中 DMEM 为 16 KiB（0x8000–0xBFFF）；B1~B5 的静态数据小于 2 KiB，最大栈深度小于 4 KiB，运行时库小于 1 KiB |
| AS-04 | 用户规模为 1~3 人，无并发、无多用户、无权限隔离需求 | 课程设计场景 |
| AS-05 | 单次编译的输入规模 ≤ 1000 行、单文件 | 目标应用（小游戏）实际规模预估上界，留 3 倍余量 |
| AS-06 | 开发在 x86-64 Linux 或 WSL2 上完成，工具链为交叉编译器 | 目标 CPU 不能自举；交叉编译是唯一可行路径 |
| AS-07 | 输出通道为 MMIO 寄存器，编译器本身不需要知道具体地址 | 编译器只生成对运行时函数的 `jal`，地址细节封装在运行时库 |
| AS-08 | 目标 CPU 不对非对齐访存做处理 | 因此编译器和运行时必须保证所有 `int` 访问 4 字节对齐（见 `CN-08`） |
| AS-09 | RV32IM 范围内的每条指令，其"有/无"都能被收敛为一组有限、互斥、可枚举的能力条件 | 见 `IF-06(c)`：`EX-01`~`EX-06` 覆盖全部对 codegen 有实际影响的指令；其余 RV32IM 指令（`mulh*`、`divu`/`remu`、`amo*`、`fence`）对 C 子集代码生成无影响或不适用，故不需要 profile 维度 |
| AS-10 | 同一 profile 的语义在整条工具链（编译器 / 汇编 / lint / 运行时库 / 硬件）中可保持一致 | 依据 `CN-16` 与 `D-10`：profile 文件是唯一事实来源，`lint.sh` 与 `build.sh` 从其派生，不使用硬编码清单 |
| **AS-11** | **图形界面所依赖的 PySide6 可在开发机上安装成功；且 `QT_QPA_PLATFORM=offscreen` 在该平台上可用** | PySide6 为 `x86-64` 提供 manylinux wheel；offscreen 平台插件随 Qt 一起分发。`AC-13` 要求验证这一点，故该假设有测试支撑 |
| **AS-12** | **验收机允许预装 Python 依赖（联网 `pip install` 或使用随项目附带的 wheel），且"装不上"时退回纯 CLI 不构成验收失败** | `NFR-506` 提供离线安装路径；`AC-12` 规定 GUI 不可用时 P0 验收项仍须成立；`RO-06` 的角色定义即为此场景 |
| **AS-13** | **WSL2 环境下存在可用的图形通道（WSLg 或已配置的 X server）；若无，则按 `FM-17` 退回 CLI** | `AS-06` 允许 WSL2；WSLg 在 Windows 11 上默认可用；不假设其必然存在，而是把它作为可降级条件 |

### 3.2 约束

| 编号 | 约束 | 理由 / 影响 |
|---|---|---|
| **CN-01** | 实现语言：Python 3.11+。**`core`（`lexer`/`parser`/`types`/`sema`/`codegen`/`isa`/`driver`）与 `cli` 仅使用标准库；`gui` 额外允许且仅允许 PySide6**（唯一白名单第三方依赖，见 `CN-14`/`CN-18`） | v1.0/v1.1 时为"全部仅标准库"；v1.2 **首次放开**，理由见 `BG-07` 与 `D-08`。代价显式登记为：`NFR-501` 放宽、新增 `NFR-506`（离线安装）与 `RO-06`（环境准备者角色）、`NFR-301` 加前提条件 |
| **CN-02** | 目标 ISA 由选定 profile 派生，恒为 RV32IM 的子集，且恒为"CPU 实际支持集"的子集；默认 profile 为 `PF-01 base`（26 条）；profile 必须包含 `MV-ISA`（9 条） | 保证生成代码必然可运行于当前目标 CPU；同时允许按硬件实际能力裁剪 |
| CN-03 | 汇编、链接、格式转换由标准 riscv-gnu-toolchain 承担，不自研汇编器 | 避免重复实现 `%hi`/`%lo` 重定位、段与符号表 |
| CN-04 | 单文件编译，不支持多翻译单元与链接期符号解析 | 目标应用无此需求；引入后工作量翻倍 |
| CN-05 | 不实现预处理器 | 无 libc、无头文件需求；运行时函数声明直接写在源码中 |
| CN-06 | 生成非位置无关代码（非 PIC），不生成 `auipc` | 目标为裸机固定加载地址。注：启用 `EX-06` 不等于启用 PIC |
| CN-07 | 目标文件由链接脚本固定 `.text` 起始地址，与 CPU 的 IMEM 映射一致 | 与既有内存映射方案对齐 |
| CN-08 | 所有 `int`、指针、数组元素 4 字节对齐；栈帧大小按 16 字节对齐 | 见 `AS-08`；ABI 要求 `sp` 16 字节对齐 |
| CN-09 | 函数参数个数上限为 8（`a0-a7`） | 超出即报"不支持"（`FR-509`），不实现压栈传参 |
| CN-10 | 编译器与运行时**不生成** `ecall`、CSR 指令、`URET`、`DIVU`、`REMU` | 避免牵扯异常/陷入处理。注：硬件已有的 `divu`/`remu` 不被使用，原因是本语言无无符号整型（`FR-404`），除法/取余一律按有符号处理（`D-11`） |
| CN-11 | 编译器诊断信息使用英文；命令行输出与日志使用英文；**工作台界面文字使用中文，但其中转述的诊断文本保持英文原文** | 与 gcc/clang 惯例一致；同时保证 `FR-906`/`FR-911` 中"诊断文本在 GUI 与 CLI 之间逐字一致"可验证 |
| CN-12 | profile 由人显式声明，编译器不做硬件能力自动探测 | 裸机无自省能力（`NG-11`）；一致性由 `AC-10` 的比对检查保证 |
| **CN-13** | **`core` 不得依赖任何 front-end**：`core` 模块内不得 `import` `cli`/`gui`/`PySide6`，不得写 stdout/stderr，不得直接读写文件（除由调用方传入的路径参数），**不得创建 `QApplication` 或任何 Qt 对象** | 这是 GUI 与 CLI 共用同一内核、且 GUI 可被 offscreen 无头测试的前提；由静态检查脚本强制（`FR-810`、`NFR-401`） |
| **CN-14** | **工作台仅使用 PySide6 作为 GUI 框架；不得引入 PyQt5/PyQt6、Kivy、wxPython、Dear PyGui 等任何其他第三方 GUI 框架，也不得引入浏览器前端技术栈** | 依赖白名单必须封闭，否则 `CN-18` 无从执行；`D-08` 记录选型理由与备选否决原因 |
| CN-15 | 语言子集与 ISA profile 严格解耦：profile 只影响"同一语言程序如何被翻译"，不影响"哪些语言构造被接受"。`EX-05`（`lb`/`lbu`/`lh`/`lhu`）不得自动解锁 `char`/`short`；解锁需显式 `--lang=char`（P1，且默认关闭） | 否则"同一份源码能否编译"会随硬件配置漂移，破坏需求的可验证性与可移植性 |
| CN-16 | profile 文件是"目标 ISA 事实"的唯一来源：编译器、`lint.sh`、`build.sh`、运行时库汇编预处理四处必须由其派生，禁止在任何一处硬编码指令清单 | 消除"编译器与硬件不一致"这一整类故障（`FM-12`/`FM-16`）；`AS-10` 的依据 |
| CN-17 | CLI 的功能集是 GUI 功能集的超集：任何 P0 需求与任何 `AC-01`~`AC-10` 判据都不得只能通过 GUI 达成；GUI 专属的能力仅限"可视化" | 保证 `AC-08` 的一键复现不依赖图形环境（`AC-12`、`NFR-807`） |
| **CN-18** | **依赖白名单是封闭的**：除 PySide6 外，任何新增第三方依赖（含 pytest/coverage 以外的运行期依赖、以及任何前端资源）都必须走附录 C 的变更控制，并在 `§3.3` 依赖表与 `requirements.txt` 中登记并锁定版本 | `CN-01` 一旦放开一个口子，就必须给出防止其扩大的机制，否则"仅标准库"会在实现期被逐步侵蚀；这也是 `RS-20` 的对策 |
| **CN-19** | **PySide6 以 LGPLv3 使用**：交付形态为源码 + `requirements.txt`，不静态链接、不打包分发；`gui` 源码中标注所使用的 PySide6 版本与许可 | 履行 LGPLv3 的最简路径；同时与既有的"不做打包分发"决定一致（§9.3） |

```
  --isa-file <path>       从 JSON 文件载入指令集配置
  --enable <list>         启用可选组或单条指令（逗号分隔）
  --disable <list>        禁用可选组或单条指令（逗号分隔，优先于 --enable）
  --no-lui                兼容别名，等价 --disable lui
  --no-vshift             兼容别名，等价 --disable vshift
  --lang <list>           语言扩展开关（默认空，即 P0 子集；可选 char）
  --dump-tokens           打印 token 流到 stdout
  --dump-ast              打印带缩进的 AST 到 stdout
  --dump-ir               打印中间表示到 stdout
  --dump-isa              打印当前 profile 的指令清单与替代路径
  --dump-isa-whitelist    逐行打印机器指令助记符（供 lint 消费）
  --dump-lowering-report  打印每条被选中的 lowering 规则及原因
  --gui [<file>]          启动图形工作台
  --doctor                环境自检：Python / PySide6 / Qt 平台插件 / 工具链，含修复命令
  --stats                 在 stderr 打印各阶段耗时
  --version               打印版本、目标 ISA 标识、当前 profile 名、工作台可用性与 PySide6 版本
  -h, --help              打印帮助
```

**退出码**（遵循 `sysexits.h` 惯例）

| 码 | 含义 | 触发条件 |
|---|---|---|
| 0 | 成功 | 生成输出文件（或工作台正常启动与退出） |
| 1 | 源程序错误 | 词法/语法/语义错误；使用了不支持的构造；**某操作在选定 profile 下无可用 lowering（`FM-15`）** |
| 2 | 编译器内部错误 | 断言失败或未捕获异常（`FR-704`） |
| 64 | 命令行用法错误 | 选项非法、缺少输入文件、多个输入文件；`--enable`/`--disable` 组合导致 profile 缺 `MV-ISA` 或不可满足（`FM-14`）；无图形环境或 PySide6 缺失时启动 `--gui`（`FM-17`） |
| 65 | 输入数据错误 | 源文件非 UTF-8；profile 文件不可读/非法 JSON/字段非法/未知字段（`FM-13`） |
| 66 | 输入文件不可读 | 不存在、无权限、是目录 |
| 70 | 输出写入失败 | 目录不存在、无权限、磁盘满 |
| 71 | 环境自检失败（`--doctor`） | 发现必需组件缺失（仅在 `--doctor` 下使用；正常编译路径不使用该码） |

**验收标准**：`mycc`（无参数）→ 64；`mycc a.c b.c` → 64；`mycc 不存在.c` → 66；`mycc -ioops a.c` → 64；`mycc -o /nonexistent/x.s 合法.c` → 70；`mycc --disable jalr a.c` → 64 且 stderr 含 `MV-ISA`；`mycc --isa-file /dev/null a.c` → 65；`env -u DISPLAY mycc --gui a.c` → 64。以上八者均在 stderr 输出说明，且均不产生输出文件。

### 6.2 IF-02｜输入：语言子集文法

完整文法见附录 A。要点：
- 编码：UTF-8（可含 BOM），换行 `\n` 或 `\r\n`
- 扩展名：`.c`（不强制，但不以 `.c` 结尾时给出警告）
- 最大规模：1000 行 / 128 KiB（超出报错，`FM-09`）
- 每个源文件必须包含且仅包含一个 `int main(void)` 定义（`FR-412`）
- **语言子集由 `--lang` 与 P0 定义决定，与 profile 无关（`CN-15`）**

### 6.3 IF-03｜输出：汇编文本格式

| 项 | 规定 |
|---|---|
| 语法 | GNU as（RISC-V）语法，目标体系 `riscv32` |
| 段 | 至少包含 `.section .text`，可选 `.section .rodata`、`.data`、`.bss` |
| 符号 | 每个全局函数与变量使用 `.globl <name>`；符号名按 C 标识符原样输出（不加下划线前缀） |
| 位置无关 | 不生成 PIC 相关重定位；不生成 `auipc` |
| 指令 | 机器指令严格属于**当前 profile 派生集**；允许使用 gas 伪指令（`li`/`la`/`mv`/`ret`/`j`），但其展开结果必须仍属该集合 |
| 调试信息 | 不生成 `.cfi` 指令（P0）；P2 可选 |
| 汇编兼容 | 必须能通过 `-mno-relax` 选项无警告汇编 |
| 可复现性 | 同一输入 + 同一 profile 指纹 → 输出逐字节相同（`FR-107`） |

### 6.4 IF-04｜诊断信息格式

**文本形式（CLI stderr）**

```
<file>:<line>:<col>: <severity>: <message>
<源行原文>
<spaces><caret>

[note: <附加说明，最多一条>]
```

实例一（`SC-03`，语言层不支持）：
```
demo.c:7:1: error: 'char' is not supported by this compiler (mycc supports 'int' only)
char c = 'A';
^~~~~
note: use 'int' instead; character literals such as 'A' are supported with type 'int'
```

实例二（`FM-15`，profile 无法表达某操作）：
```
mycc: error: profile 'custom-x' cannot compile this program
  abstract operation : signed less-than comparison
  required (any of) : blt | slt | sltu
  currently disabled : blt, slt, sltu
  suggestion         : --enable cmpbr, or use --profile PF-01
```

**结构化形式（供工作台消费，`FR-708`）**

每条诊断同时作为一个记录（字段名固定，供 `FR-906`/`FR-911` 使用）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | 字符串 | 是 | 源文件路径（与命令行给出的形式一致） |
| `line` | 整数 | 是 | 1 基 |
| `col` | 整数 | 是 | 1 基，按 Unicode 码位计 |
| `end_col` | 整数 | 否 | 用于画段标记（如 `^~~~~` 的长度）；缺省等于 `col` |
| `severity` | 枚举 | 是 | `error` / `warning` / `note` |
| `code` | 字符串 | 是 | 稳定诊断码（如 `E-UNSUPPORTED-CONSTRUCT`），供测试断言与文档索引 |
| `message` | 字符串 | 是 | 英文消息体 |
| `note` | 字符串 | 否 | 最多一条附加说明 |
| `stage` | 枚举 | 是 | `lex` / `parse` / `sema` / `profile` / `codegen` / `internal` |

- 列数为 1 基，按 Unicode 码位计
- 行长为 0 或行内含制表符时，caret 行按制表符宽度 4 展开
- **所有诊断文本输出到 stderr（`FR-703`）；结构化记录不写 stdout**
- **诊断文本在工作台与 CLI 中逐字一致**（`FR-906`、`CN-11`）

### 6.5 IF-05｜运行时库 ABI

| 函数 | 签名 | 语义 | 是否可能被编译器自动生成调用 |
|---|---|---|---|
| `_start` | — | 初始化 `sp`、清零 `.bss`、`call main`、`a0` 传 `exit` | 否（由链接脚本指定入口） |
| `putchar` | `void putchar(int c)` | 低 8 位为字符，写串口 MMIO + VGA 文本缓冲区 | 否（仅显式调用） |
| `printint` | `void printint(int x)` | 十进制有符号输出，含负号 | 否 |
| `printhex` | `void printhex(int x)` | `0x` + 8 位十六进制 | 否 |
| `exit` | `void exit(int code)` | MMIO 输出状态码并自旋 | 否 |
| `__mulsi3` | `int __mulsi3(int a, int b)` | 32 位有符号乘法（低 32 位） | 仅当 `EX-01` 未启用时（`FR-510`） |
| `__divsi3` | `int __divsi3(int a, int b)` | 有符号除法，向零取整；`b == 0` 返回 `-1`，`INT_MIN / -1` 返回 `INT_MIN`（对齐硬件语义，`D-11`） | 仅当 `EX-02` 未启用时 |
| `__modsi3` | `int __modsi3(int a, int b)` | 有符号取余，符号同被除数；`b == 0` 返回被除数 `a`（对齐硬件语义，`D-11`） | 仅当 `EX-02` 未启用时 |
| `__ashlsi3` / `__lshrsi3` / `__ashrsi3` | `int f(int a, int n)` | 逻辑/算术移位，`n ≥ 32` 或 `n < 0` 时结果未定义 | 仅当 `vshift` 组被禁用时（`FR-518`） |
| `memcpy` / `memset` | `void* memcpy(void*, const void*, unsigned)` / `void* memset(void*, int, unsigned)` | 提供但不由编译器自动生成（P0 无 `char`、无结构体赋值） | 否（P1 之后可能） |

**参数传递**：全部走 `a0`~`a7`，结果在 `a0`；不使用栈传参（`CN-09`）。
**条件汇编**：`runtime.s` 以 `.ifdef HAVE_MUL` / `HAVE_DIVREM` / `HAVE_VSHIFT` 等符号控制可选函数的包含，符号由 `build.sh` 依据 profile 以 `--defsym` 传入（`FR-613`）。

### 6.6 IF-06｜目标 ISA 依赖清单

#### (a) MV-ISA：最小可行 ISA（9 条，任何 profile 必须包含，无 lowering 回退）

| 指令 | 若缺失则无法表达 |
|---|---|
| `add` `sub` `addi` | 整数算术与地址计算（含取负） |
| `lw` `sw` | 栈帧、局部变量、数组访问 |
| `beq` `jal` | 条件转移与直接调用（`bne`/`bge`/`blt` 等均可由其合成） |
| `jalr` | 函数返回与间接跳转（不可合成） |
| `slt` | 有符号比较、全部关系运算与 `sltu` 合成的基础 |

> MV-ISA 是 `AS-01` 中 22 条已有指令的子集，故**真实硬件恒满足**；该校验的目的是拦住用户自定义 profile 文件中的错误（`FM-13`/`FM-14`）。

#### (b) 基础组：`PF-01 base`（26 条 = MV-ISA 9 条 + 以下 17 条）

| 类别 | 指令 | 现状 |
|---|---|---|
| 寄存器算术/逻辑 | `and` `or` `sltu` | **已有** |
| 寄存器移位 | `sll` `srl` `sra` | **需新增（3 条）** |
| 立即数算术/逻辑 | `andi` `ori` `xori` `slti` | **已有** |
| 立即数移位 | `slli` `srli` `srai` | **已有** |
| 高位立即数 | `lui` | **需新增（1 条）** |
| 访存 | `sb` | **已有** |
| 控制转移 | `bne` `blt` | **已有** |

> **合计需新增 4 条指令：`lui`、`sll`、`srl`、`sra`。**
> 基础组还包含两个可禁用的子集（保留 v1.0 的降级语义）：`lui`（单条）与 `vshift` = {`sll`,`srl`,`sra`}。

#### (c) 可选扩展组 EX-01 ~ EX-06

| 组 | 组名 | 指令 | 启用后 codegen 的变化 | 依赖 | 备注 |
|---|---|---|---|---|---|
| **EX-01** | `mul` | `mul` | `*`：由 `call __mulsi3` 变为单条 `mul` | 无 | 只需 `mul`，不需要 `mulh`/`mulhu`/`mulhsu`（`int` 乘法只要低 32 位） |
| **EX-02** | `divrem` | `div` `rem` | `/`、`%`：由运行时调用变为单条指令 | 无 | 组内 `div` 与 `rem` 可分别启停；仅启用 `div` 时 `%` 生成为 `a - (a/b)*b` |
| **EX-03** | `xor` | `xor` | `^`：由 3 条合成变为 1 条 | 无 | 纯代码质量 |
| **EX-04** | `cmpbr` | `bge` `bgeu` `bltu` `sltiu` | 比较分支：2 条 → 1 条；常量上界检查：2 条 → 1 条 | 无 | 纯代码质量 |
| **EX-05** | `byteload` | `lb` `lbu` `lh` `lhu` | 不改变 codegen：仅在 `--lang=char` 启用后解除对 `char`/`short` 的硬件依赖 | 硬件 `sb`（已有） | 受 `CN-15` 约束：启用本组不自动解锁 `char`；默认 `--lang` 为空时本组"启用了也不产生任何代码差异" |
| **EX-06** | `auipc` | `auipc` | 不使用 | 无 | 明确默认不启用；启用亦不生成 PIC（`CN-06`）。保留该组仅为"profile 能完整描述硬件能力"之意 |

**组别名**（供 `--enable`/`--disable` 使用）：`m` = `EX-01` + `EX-02`；`lui` = {`lui`}；`vshift` = {`sll`, `srl`, `sra`}。

> 硬件已有的 `divu`/`remu` 不在任何组内：本语言无无符号整型（`FR-404`），编译器不需要它们（`CN-10`）。

#### (d) 抽象操作 × 降级路径对照表（**本项目的核心机制**）

| 抽象操作 | 首选路径（能力守卫） | 回退路径（守卫不成立时） | 相关需求 |
|---|---|---|---|
| 32 位常量加载 | `lui` 属于 ISA 且值超 12 位 → `lui`+`addi` | `addi`+`slli`+`addi`+`slli`（4 条） | `FR-505`、`FR-517` |
| 有符号 `<` | `blt` 属于 ISA → `blt` | `slt`+`bne` | `FR-506`、`EX-04` |
| 无符号 `<` | `bltu` 属于 ISA → `bltu` | `sltu`+`bne` | `FR-506`、`EX-04` |
| 有符号 `>=` | `bge` 属于 ISA → `bge` | `slt`+`beq` | `FR-506`、`EX-04` |
| 常量上界检查 | `sltiu` 属于 ISA → `sltiu` | `addi`+`sltu` | `FR-506`、`EX-04` |
| `^` | `xor` 属于 ISA → `xor` | `(a\|b) - (a&b)`（3 条） | `FR-515`、`EX-03` |
| `*` | `mul` 属于 ISA → `mul` | `call __mulsi3` | `FR-510`、`EX-01` |
| `/` | `div` 属于 ISA → `div` | `call __divsi3` | `FR-510`、`EX-02` |
| `%` | `rem` 属于 ISA → `rem`；否则 `div` 属于 ISA → `a-(a/b)*b` | `call __modsi3` | `FR-510`、`EX-02`、`FR-1003` |
| 变量移位 | `vshift` 是 ISA 子集 → `sll`/`srl`/`sra` | `call __ashlsi3`/`__lshrsi3`/`__ashrsi3` | `FR-518` |
| 乘以 2 的幂常量 | 与 ISA 无关，恒为 `slli`（负数乘数再配 `sub`） | — | `FR-510` |

> 表中每条回退路径的展开只用 MV-ISA 与基础组的已有指令，这是 `FR-520` 兜底规则成立的前提。

#### (e) 明确不受 profile 影响的指令

`ecall`、CSR 指令、`URET`、`divu`、`remu`、`fence`、`amo*` —— 编译器在任何 profile 下都不生成（`CN-10`）。

### 6.7 IF-07｜ISA profile 文件格式（JSON）

```json
{
  "name": "board_v2",
  "description": "FPGA 板卡 v2：已补 lui/sll/srl/sra，含乘法器，无除法器",
  "schema_version": 1,
  "instructions": [
    "add", "sub", "addi", "lw", "sw", "beq", "jal", "jalr", "slt",
    "and", "or", "sltu", "bne", "blt", "sb",
    "andi", "ori", "xori", "slti", "slli", "srli", "srai",
    "lui", "sll", "srl", "sra",
    "mul", "xor"
  ]
}
```

| 字段 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `name` | 是 | 字符串 | `[A-Za-z0-9_-]{1,64}`；与内置 profile 名不冲突 |
| `description` | 否 | 字符串 | ≤ 200 字符，用于 `--dump-isa` 与工作台显示 |
| `schema_version` | 是 | 整数 | 当前为 `1`；不等则报 `FM-13` 并提示升级 |
| `instructions` | 是 | 字符串数组 | 元素属于 `IF-06` 全集；无重复；必须包含 MV-ISA |

**规则**
- 未知字段必须报错（不静默忽略），以便及早发现拼写错误。
- 未知指令名必须报错，并给出"最接近的合法名"建议（编辑距离 ≤ 2）。
- 指令清单是能力集合，顺序不影响语义；profile 指纹 = 排序去重后清单的 SHA-256（`FR-1004`）。
- 硬件侧清单（`DP-08`）使用同一 schema，因此可直接与 profile 做集合比对（`FR-614`）。

**线程与进程模型（约束性规定）**

| 工作 | 执行位置 | 依据 |
|---|---|---|
| 编译（`core.compile`） | `QThreadPool` 中的一个 `QRunnable` / `QThread` | `FR-904`、`NFR-802` |

## 8. 优先级与迭代计划

### 8.1 优先级定义

| 级别 | 判据 | 缺失后果 |
|---|---|---|
| **P0（必须）** | 每次编译都会用到，或缺少它则链路断裂、无法演示、无法验证 | 课程设计不成立 |
| **P1（应当）** | 常见场景会用到，或用于风险兜底与质量提升 | 显著降低可用性/演示效果，但主体可交付 |
| **P2（可选）** | 罕见场景，或有更简单的替代做法 | 无实质影响 |

**v1.2 优先级定位的显式结论**

| 主题 | 级别 | 理由 |
|---|---|---|
| **可选指令集机制** | **P0** | 它决定"生成代码的正确性边界"，且与硬件演进强绑定（`BG-05`）；lowering 机制（`FR-519`）必须在写 codegen 时一并建立，事后补做等于重写 codegen 的指令选择部分 |
| **图形工作台** | **P1** | `CN-17` 保证 CLI 功能完备，`AC-01`~`AC-10` 全部可由 CLI 达成；把工作台定为 P0 会引入两处风险——一是把"图形环境可用"变成验收前提（违反 `AC-12`），二是让展示层进入 M1~M3 关键路径（`RS-14`）。**该取舍是可逆的**：若课程对"不同用户的人机界面"评分权重更高，可将 `FR-901`~`FR-919` 升为 P0，并同步修改 `AC-12` 中"GUI 测试 skipped 可接受"的措辞 |
| **工作台的 offscreen 可测性**（`FR-919`、`FR-920`、`NFR-803`、`NFR-807`） | **P0** | 它们是"工作台定为 P1 但不失控"的前提：没有 offscreen 可测性，GUI 就会变成无验证代码（`RS-11`）；这部分成本很低但收益是让 `AC-13` 可自动化 |

**优先级与频率的一致性校验**（课程评分项）：本文档中所有 P0 需求的"频率"列均为"每次 / 常见"。需要解释的例外：

| 条目 | 频率 | 级别 | 理由 |
|---|---|---|---|
| `FR-112`（`--enable`/`--disable`） | 常见 | P0 | 它是 `FR-109` 的取代者与 `RS-01` 的唯一缓解手段；且 lowering 机制必须与 codegen 同批建立 |
| `FR-1001` / `FR-1002`（EX 组与 profile 定义） | 每次 | P0 | 同上：机制是 P0，**具体某个可选组是否在本轮实现可另行裁剪**（见 §8.2） |
| `FR-117` / `FR-521`（lowering 报告与原因文本） | 开发期高频 | P1 | 非链路必需，但它是工作台 `FR-909` 的数据源，也是"演示说服力"的核心 |
| `FR-517` / `FR-518` | 仅风险期 | P1 | 触发条件已由开关改为能力谓词 |
| `FR-901`~`FR-918`（工作台） | 开发期每日 / 演示 | P1 | 见上表 |
| `FR-911`（导出）、`FR-918`（大文件保护）、`FR-1005`（变更影响报告） | 偶尔 / 罕见 | P2 | 锦上添花 |
| `NFR-310`（回路耗时 ≤ 15 s） | — | P1 | 它是 `G-06` 的判据，但 `G-06` 对应的能力整体为 P1 |
| `NFR-104`（生成代码质量） | — | P1 | 阈值有 3 倍余量，且不达标不影响链路的正确性 |

## 9. 范围边界

### 9.1 In Scope

**语言构造**（附录 A 全量，P0）：
- 类型：`int`、`int*`、`int[N]`、`void`（仅返回类型）
- 全局变量、全局数组（含 `{}` 常量初始化）
- 函数：`int`/`void` 返回，参数 ≤ 8 个，支持递归
- 语句：块、`if/else`、`while`、`for`、`return`、`break`、`continue`、表达式语句、块内声明
- 运算符：算术 `+ - * / %`、比较 `== != < <= > >=`、逻辑 `&& || !`、位运算 `& | ^ ~ << >>`、赋值与复合赋值、`++/--`、`[]`、函数调用、`sizeof`
- 字面量：十进制/十六进制/八进制整数、字符字面量（类型为 `int`）
- 注释：`//` 与 `/* */`

**指令集机制（P0）**：`IF-06` 的 MV-ISA 与基础组（26 条）、`EX-01`~`EX-04` 的 lowering 规则、`EX-06`（无代码影响）、`PF-01`~`PF-07` 内置 profile、JSON profile 载入与校验、lowering 表与能力谓词机制、`--dump-isa` / `--dump-isa-whitelist` / `--dump-lowering-report`、ISA 一致性检查、`--doctor`、依赖白名单检查。

**工具与集成（P0）**：`mycc` CLI、`runtime.s`（含条件汇编）、`build.sh`、`lint.sh`、`compare.sh`、`check_isa_consistency.sh`、链接脚本、`check.sh`、profile 不变性测试、测试与覆盖率报告。

**图形工作台（P1）**：`FR-901`~`FR-910`、`FR-912`~`FR-917`、`FR-919`、`FR-920` 与 `NFR-8xx`。**其中 `FR-919`/`FR-920`/`NFR-803`/`NFR-807` 按 P0 要求实施**（见 §8.1）。

### 9.2 Deferred（明确延后，编号保证可追溯）

| 特性 | 阶段 | 阻塞原因 |
|---|---|---|

### 9.3 Out of Scope（明确不做，含理由）

| 不做 | 理由 |
|---|---|
| 浮点（`float`/`double`） | 硬件无 FPU；软件浮点是一个独立项目 |
| 可变参数（`...`）与 `va_list` | 需要完整的栈传参机制，与 `CN-09` 冲突 |
| 函数指针、函数声明与定义分离的复杂情形 | 需要更复杂的类型系统与重定位 |
| 位域、`long long`、`unsigned` 类型族 | 与 `int`-only 子集不兼容；也是 `divu`/`remu` 不被使用的原因（`CN-10`） |
| `goto` 与标签 | 会破坏结构化 codegen 的标签管理 |
| 逗号运算符 | 极少使用；已有块级表达式语句可替代 |
| 完整预处理器（`#include`/条件编译/宏函数） | `CN-05`；无 libc，运行时函数声明直接书写 |
| 标准库（`string.h`、`stdlib.h` 等） | 裸机环境；必要功能由 `runtime.s` 以最小接口提供 |
| 优化（内联、寄存器分配、循环优化、常量传播、公共子表达式消除） | `NG-02`；`FR-501` 已明确选择无优化路径 |
| 自举、跨平台后端（x86/ARM 目标） | `NG-03`；单一后端 |
| 自研汇编器与链接器 | `NG-04`、`CN-03` |
| 生成调试信息（`.cfi`/DWARF） | 目标平台无调试器 |
| 并发编译、增量编译 | 输入规模 ≤1000 行，无必要（`AS-04`） |
| 硬件能力自动探测 | `NG-11`；裸机无自省能力 |
| 全 profile 组合穷举验证 | `NG-10`；改为 profile 矩阵 + 不变性属性（`AC-09`） |
| **PySide6 以外的第三方 GUI 框架**（PyQt5/PyQt6、Kivy、wxPython、Dear PyGui） | `CN-14`；依赖白名单必须封闭（`CN-18`） |
| **Web UI / 浏览器前端**（含 `http.server` 自建方案与任何前端资源） | v1.2 选型时列为备选（`D-08`），因以下三条被否决：① 浏览器沙箱使"另存为指定路径"不可实现，与"IDE 式工作台"的日常使用诉求（`G-06`）直接冲突；② 需要放开 `NFR-603` 并新增回环安全面（Origin 校验、随机 token）；③ 项目不再有理由引入第二套渲染与状态同步技术栈 |
| **自研 GUI 框架层**（自绘控件、主题引擎、编辑器内核） | `NG-12`；在 PySide6 之上再造框架只增加无测试覆盖的代码（`RS-20`） |
| **IDE 类功能**：项目管理、多文件工程、版本控制集成、断点/单步调试、内嵌指令集模拟器 | `NG-09`；"运行"是外部工具链调用（`FR-910`），不是内嵌仿真 |
| **打包分发**（PyInstaller/单文件可执行） | 交付形态为源码 + `requirements.txt`；打包会引入与核心目标无关的构建复杂度，且与 `CN-19` 的最简 LGPL 履约路径相悖 |

## 附录 A：C 子集文法

### A.1 顶层结构

```ebnf
program        ::= top_item* ;
top_item       ::= func_def | global_decl ;

func_def       ::= ( "int" | "void" ) IDENT "(" param_list? ")" "{" block_item* "}" ;
param_list     ::= param ( "," param )* ;              (* 个数 <= 8，见 CN-09 *)
param          ::= "int" IDENT ( "[" "]" )? ;

global_decl    ::= "int" IDENT ( "[" INT_LIT "]" )? ( "=" init )? ";" ;
init           ::= const_expr | "{" const_expr ( "," const_expr )* "}" ;
```

### A.2 语句

```ebnf
block_item     ::= stmt | local_decl ;
local_decl     ::= "int" IDENT ( "[" INT_LIT "]" )? ( "=" expr )? ";" ;

stmt           ::= compound | ";"
                 | "if" "(" expr ")" stmt ( "else" stmt )?
                 | "while" "(" expr ")" stmt
                 | "for" "(" expr? ";" expr? ";" expr? ")" stmt
                 | "return" expr? ";"
                 | "break" ";"
                 | "continue" ";"
                 | expr ";" ;
compound       ::= "{" block_item* "}" ;
```

> **文法与 profile 无关**（`CN-15`、`FR-415`）：profile 的任何配置都不得改变本文法。

### A.3 词法元素

| 类别 | 定义 |
|---|---|
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*`，长度 ≤ 255 |
| `INT_LIT` | `[0-9]+` \| `0[xX][0-9a-fA-F]+` \| `0[0-7]*`；值范围 0 ~ 4294967295（超出报错） |
| `CHAR_LIT` | `'`（单个字符 \| `\n` `\t` `\r` `\0` `\\` `\'` `\"`）`'` |
| 关键字 | `int` `void` `if` `else` `while` `for` `return` `break` `continue` `sizeof` |
| 运算符/分隔符 | `+ - * / % ++ -- = += -= *= /= %= == != < <= > >= && \|\| ! & \| ^ ~ << >> <<= >>= &= \|= ( ) [ ] { } ; ,` |
| 注释 | `//` 至行尾；`/*` 至 `*/`（不可嵌套） |

> 关键字表**故意不含** `char` `short` `long` `unsigned` `struct` `union` `enum` `typedef` `switch` `case` `default` `goto` `do` `double` `float` `const` `static` `extern` `volatile` `signed`。这些标识符被词法器识别为**保留但不受支持**的关键字，用于产出 `FR-409` 的专门诊断（而非被当作普通标识符，从而避免产生令人困惑的"未声明标识符"错误）。

### A.4 运算符优先级（由低到高）

| 级别 | 运算符 | 结合性 |
|---|---|---|
| 1 | `= += -= *= /= %= &= \|= <<= >>=` | 右 |
| 2 | `\|\|` | 左 |
| 3 | `&&` | 左 |
| 4 | `\|` | 左 |
| 5 | `^` | 左 |
| 6 | `&`（二元） | 左 |
| 7 | `== !=` | 左 |
| 8 | `< <= > >=` | 左 |
| 9 | `<< >>` | 左 |
| 10 | `+ -` | 左 |
| 11 | `* / %` | 左 |
| 12 | `+ - ! ~ * & ++ --`（前缀）、`sizeof` | 右 |
| 13 | `[] ()`（后缀）、`++ --`（后缀） | 左 |
| 14 | 字面量、标识符、`( expr )` | — |

解析方法：优先级爬升（precedence climbing），级别 12/13 由一元解析例程处理。

### A.5 语义规则要点

| 规则 | 说明 |
|---|---|
| 类型宽度 | `int`、`int*` 均为 4 字节 |
| 数组退化 | 数组名在表达式中退化为 `int*`，指向首元素 |
| 指针算术 | `int* + int` → 按 4 字节缩放；指针相减结果为 `int`（元素个数） |
| 下标 | `a[i]` ≡ `*(a + i)`；`a` 可为数组名或指针 |
| 比较 | 指针比较按无符号；`int` 比较按有符号 |
| 整数运算 | 无符号整型族不存在，所有运算按 32 位有符号补码，溢出为环绕（不报错） |
| 除法/取余 | 向零取整；`b == 0` 与 `INT_MIN / -1` 的语义**显式定义为与 RISC-V 硬件一致**（`D-11`、`FR-606`），使启用与未启用 `EX-02` 的行为相同 |
| 布尔化 | 条件表达式的真值为"非零"；`&&` `\|\|` `!` 的结果为 `0` 或 `1` |
| 未初始化局部变量 | 值为未定义；编译器不做零初始化（全局变量在 `.bss` 中由 `_start` 清零） |
| 参数传递 | 值传递；`int` 与 `int*` 均占一个参数槽 |
| 返回 | `void` 函数不得 `return expr;`；`int` 函数必须 `return`，路径缺失为 P1 警告（`FR-413`） |
| **与 profile 的关系** | **本节全部规则与 profile 无关**；profile 只影响"如何翻译"，不影响"翻译成什么语义"（`CN-15`） |

## 附录 C：需求变更控制流程

1. **提出**：任何新增/修改/删除需求，须在修订记录中登记（版本号、日期、提出人、理由）。
2. **影响分析**：识别受影响的需求项（通过 §11 追溯矩阵反查）与测试用例；判断是否突破 §9.1 的 In Scope 边界。
3. **判定**：
   - 属于 §9.3（Out of Scope）→ 直接拒绝，记录理由。
   - 属于 §9.2（Deferred）→ 变更优先级字段，不改变实现顺序，除非同时有不达标风险的缓解需求。
   - 其他 → 需在 `NFR-701` 的里程碑时间表内评估是否可容纳。
4. **同步**：受影响的需求条目、追溯矩阵（§11.2）、测试用例三者必须在同一次提交中一并更新。**任何一项缺失即视为变更未完成。**
5. **基线**：里程碑验收通过后，该版本需求文档冻结为基线；后续变更须显式说明与基线的差异。

**变更禁忌**

- 不得在没有新测试用例的情况下修改任何 P0 需求的验收标准（否则 `AC-01`~`AC-13` 失去意义）。
- **不得以"新增可选指令组"为理由修改语言子集定义**（`CN-15`）。
- **不得在 `lint.sh`/`build.sh` 中新增任何硬编码的指令清单**（`CN-16`）。
- **不得把任何 P0 验收判据改为"仅 GUI 可达"**（`CN-17`）。
- **不得在 `core`/`cli` 中引入任何第三方运行期依赖**（`CN-01`、`CN-18`）。
- **不得放宽 `CN-14` 的框架白名单**（即不得为工作台引入第二种 GUI/前端技术栈）；如确有必要，必须同时更新 `NFR-501`、`FR-812`、`§9.3` 与 `D-08`。
