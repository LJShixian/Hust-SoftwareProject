## 1. 背景与目标

### 1.1 背景

**BG-01｜硬件侧现状**
项目已实现一台自研 RISC-V CPU（Logisim 单周期原型 + 五段流水线版本，正在迁移至 FPGA/Verilog）。已实现指令集为 RV32I 的一个真子集，另含部分 RV32M（仅 `DIVU`/`REMU`）、部分 Zicsr 以及一条自定义的 `URET`。已具备数据前递的流水线冒险处理，单周期版本已实现三级嵌套中断（软件栈保存现场 + 独立优先级栈）。

**BG-02｜软件侧现状**
目前所有上机程序均为手写汇编。手写汇编存在三个具体问题：
1. 无法表达稍复杂的算法（递归、数组、指针）而不产生大量易错代码；
2. 手写过程中误用 CPU 未实现的指令（如 `lui`、`lb`）不会在汇编阶段报错，只会在运行期表现为"程序跑飞"，调试成本极高；
3. 演示说服力有限——"一段 C 代码在自己的 CPU 上运行"与"一段手写汇编在运行"是两个量级的技术展示。

**BG-03｜课程要求**
本项目同时作为软件工程课程设计交付物。课程要求覆盖：需求分析、设计、实现、测试、文档、验收演示，并对需求文档的**正确性、完备性、无二义性、可验证性、优先级合理性、可追溯性**评分。

**BG-04｜既有探索结论**
此前评估过的替代方案及其结论：
- 直接使用 GCC（`-march=rv32im`）：GCC 会使用 RV32IM 全集中任何指令，无法按"我的 CPU 支持的子集"做减法；只能通过源码规避 + 后处理，需求边界不可控。
- 使用表驱动汇编器（customasm 类）：解决"拒绝非子集指令"，但不解决"从 C 生成代码"。
- 修改 binutils/LLVM 增加自定义指令：成本高，且与课程设计目标（编译器实现）不匹配。

结论：**自研编译器是唯一能同时把"语言语义"与"目标 ISA 子集边界"两个约束握在手里的方案。**

### 1.2 问题陈述

需要一个工具，把一份用受限 C 语言写的源程序，翻译成**只包含自研 CPU 所实现指令**的 RISC-V 汇编，并保证该汇编可被标准工具链组装、链接、加载到自研 CPU 上运行；同时在源程序超出该受限语言范围时，给出定位准确、可操作的诊断信息。

### 1.3 项目目标与成功判据

| 编号 | 目标 | 成功判据（可测量） |
|---|---|---|
| G-01 | 打通"C 源码 → 自研 CPU 上运行"的完整链路 | 基准程序 B1~B4（附录 B）编译产物在自研 CPU 上运行输出与在 qemu-riscv32 上运行结果逐字节一致（`AC-04`） |
| G-02 | 实现一个可用的 C 语言子集 | 附录 A 文法定义的全部构造均被实现并通过测试（`AC-01`、`AC-02`） |
| G-03 | 将目标 ISA 依赖面收敛到最小且明确 | 生成代码的反汇编结果 100% 落在 `IF-06` 白名单（26 条）内（`AC-03`） |
| G-04 | 具备工业级诊断质量 | 100% 错误含 `file:line:col`；≥90% 含可操作建议（`NFR-205`、`NFR-206`） |
| G-05 | 作为课程设计交付物完整可验收 | 一键脚本复现全部测试，含覆盖率报告（`AC-08`） |

### 1.4 非目标（明确不做）

| 编号 | 非目标 | 理由 |
|---|---|---|
| NG-01 | 完整的 C 语言（ISO C11） | 与本项目核心价值无关；子集已足够表达目标应用 |
| NG-02 | 优化编译器 / 高性能代码生成 | 硬件的性能瓶颈不在编译器；优化是独立项目 |
| NG-03 | 自举（用 mycc 编译 mycc） | 需要 libc、预处理器、完整类型系统，工作量 ≥10 倍 |
| NG-04 | 自研汇编器 / 链接器 | 已确定为复用标准 binutils |
| NG-05 | 多文件编译、多翻译单元、链接期重定位 | 见 `CN-04`；单文件已足够 B1~B5 |
| NG-06 | 浮点、可变参数、函数指针、位域、`long long` | 见 §9.3 |
| NG-07 | 为新语言（非 C）做前端 | 本项目复用 C 语法，降低教学成本 |
| NG-08 | 生成可执行文件（ELF）而非汇编 | 由 `IF-03` 的外部工具链承担 |

### 1.5 术语表

| 术语 | 定义 |
|---|---|
| **SRS** | 软件需求规格说明（本文档） |
| **C 子集 / 受限 C** | 附录 A 文法所定义的 C 语言真子集 |
| **目标 ISA** | 编译器可生成的机器指令集合，见 `IF-06` |
| **RV32I / RV32M** | RISC-V 32 位基础整数指令集 / 乘除法扩展 |
| **ABI / ILP32** | 调用约定：`int`、指针均为 32 位；参数 `a0-a7`、返回 `a0`、返回地址 `ra`、栈指针 `sp`、帧指针 `s0` |
| **MMIO** | 内存映射 I/O；本项目的输出通道 |
| **运行时库（runtime）** | 手写汇编，提供 `_start`、输出函数与软件乘除法 |
| **ICE** | 编译器内部错误（Internal Compiler Error） |
| **助记符白名单 lint** | 对 `objdump -d` 输出逐条比对各指令助记符是否在 `IF-06` 内的检查脚本 |
| **基准程序（benchmark）** | 附录 B 定义的 5 个固定验证程序 |
| **强度削减** | 把昂贵运算改写为等价廉价运算，如乘以 2 的幂常量改写为移位 |
| **DoD** | 定义完成（Definition of Done），见 §8.2 |

## 2. 使用场景

### SC-01｜编译最小程序并运行（对应 RO-01 / RO-02）

| 项 | 内容 |
|---|---|
| 触发 | 应用开发者写好 `demo.c` |
| 前置 | 已安装 riscv 工具链与 qemu；`mycc` 可执行 |
| 主流程 | ① `./mycc demo.c -o demo.s` → ② `build.sh demo.s` 产出 `demo.hex` → ③ `qemu` 或加载到 CPU 运行 → ④ 观察输出 |
| 期望 | 退出码 0；stdout 无输出（除非用 `--dump-*`）；`demo.s` 存在且机器指令全部在白名单内 |
| 异常流 | 文件不存在 → `FM-02`；源码有错 → `FM-04`~`FM-07` |
| 涉及需求 | `FR-101`、`FR-102`、`FR-105`、`FR-106`、`FR-511`、`FR-602`、`IF-01` |

### SC-02｜定位一个编译错误（对应 RO-02）

| 项 | 内容 |
|---|---|
| 触发 | 应用开发者误写 `if (a = 1)` 或漏掉分号 |
| 主流程 | 编译器输出 `demo.c:12:9: error: ...` + 源行 + caret 指向列；用户据此修改 |
| 期望 | 行号列号准确；信息含原因；不产生/不覆盖输出文件 |
| 涉及需求 | `FR-701`、`FR-702`、`FR-106`、`NFR-205` |

### SC-03｜误用子集外特性（对应 RO-02，**最高频的边界场景**）

| 项 | 内容 |
|---|---|
| 触发 | 应用开发者写了 `char c;` 或 `printf("hi")` 或 `#include <stdio.h>` 或 `double d;` |
| 主流程 | 编译器**不把它当作普通语法错误**，而给出"该特性不属于本子集"的专门诊断，并说明替代写法（若存在） |
| 期望 | 输出形如 `demo.c:7:1: error: 'char' is not supported by this compiler (mycc supports 'int' only); use 'int' instead` |
| 涉及需求 | `FR-409`、`FR-705`、`NFR-206` |

### SC-04｜修改 codegen 后回归（对应 RO-01）

| 项 | 内容 |
|---|---|
| 触发 | 修改栈帧布局或调用序列 |
| 主流程 | 运行 `./check.sh` → 单元测试 + 端到端 + lint + qemu 对照 + 覆盖率 |
| 期望 | 全部通过；任一失败测试能通过 `TC` 编号反查对应 `FR` |
| 涉及需求 | `FR-801`~`FR-805`、`NFR-403` |

### SC-05｜课程验收演示（对应 RO-03）

| 项 | 内容 |
|---|---|
| 触发 | 验收现场 |
| 主流程 | ① `./check.sh` 现场跑通全部测试；② 展示一处在 RISC-V 上的编译错误诊断；③ 展示游戏在开发板 VGA 上运行 |
| 期望 | 单命令可复现，无需现场配置；游戏可交互运行 ≥10 分钟无异常 |
| 涉及需求 | `AC-05`、`AC-08`、`NFR-207` |

### SC-06｜硬件未补齐时的降级编译（对应 RO-01，风险预案）

| 项 | 内容 |
|---|---|
| 触发 | CPU 尚未实现 `lui` 或寄存器移位，需先行验证编译器其余部分 |
| 主流程 | `./mycc demo.c --no-lui --no-vshift -o demo.s` |
| 期望 | 输出不含 `lui`/`sll`/`srl`/`sra`；功能在 qemu 上等价（`AC-02` 仍通过） |
| 涉及需求 | `FR-109`、`RS-01` |

## 3. 假设、约束与依赖

### 3.1 假设（每条附依据）

| 编号 | 假设 | 依据 |
|---|---|---|
| AS-01 | 目标 CPU 已支持：`add sub and or slt sltu addi andi ori xori slti slli srli srai lw sw sb beq bne blt jal jalr` | BG-01 中已实现指令集清单 |
| AS-02 | 可在设计周期内为 CPU 增加 `lui`、`sll`、`srl`、`sra` 四条指令 | 四条均为已有数据通路的小改动：`lui` 复用已有的 U 型立即数生成器（与 `JAL` 共用），不经过 ALU；`sll/srl/sra` 复用已有的桶形移位器，仅将移位量来源由立即数字段改为 `rs2` |
| AS-03 | 目标平台内存足以容纳运行时库、基准程序与游戏 | 内存映射中 DMEM 为 16 KiB（0x8000–0xBFFF）；B1~B5 的静态数据 < 2 KiB，最大栈深度 < 4 KiB，运行时库 < 1 KiB |
| AS-04 | 用户规模为 1~3 人，无并发、无多用户、无权限隔离需求 | 课程设计场景 |
| AS-05 | 单次编译的输入规模 ≤ 1000 行、单文件 | 目标应用（小游戏）实际规模预估上界，留 3 倍余量 |
| AS-06 | 开发在 x86-64 Linux 或 WSL2 上完成，工具链为交叉编译器 | 目标 CPU 不能自举；交叉编译是唯一可行路径 |
| AS-07 | 输出通道为 MMIO 寄存器，编译器本身不需要知道具体地址 | 编译器只生成对运行时函数的 `jal`，地址细节封装在运行时库 |
| AS-08 | 目标 CPU 不对非对齐访存做处理 | 因此编译器和运行时必须保证所有 `int` 访问 4 字节对齐（见 `CN-08`） |

### 3.2 约束

| 编号 | 约束 | 理由 / 影响 |
|---|---|---|
| CN-01 | 实现语言：Python 3.11+，**仅使用标准库** | 最短实现路径；无需构建系统；pytest/coverage 直接可用。代价：性能指标按解释型语言设定（§5.1） |
| CN-02 | 目标 ISA 严格限定为 `IF-06` 白名单（26 条机器指令） | 保证生成代码必然可运行于自研 CPU |
| CN-03 | 汇编、链接、格式转换由标准 riscv-gnu-toolchain 承担，不自研汇编器 | 避免重复实现 `%hi`/`%lo` 重定位、段与符号表 |
| CN-04 | 单文件编译，不支持多翻译单元与链接期符号解析 | 目标应用无此需求；引入后工作量翻倍 |
| CN-05 | 不实现预处理器 | 无 libc、无头文件需求；运行时函数声明直接写在源码中 |
| CN-06 | 生成非位置无关代码（非 PIC），不生成 `auipc` | 目标为裸机固定加载地址 |
| CN-07 | 目标文件由链接脚本固定 `.text` 起始地址，与 CPU 的 IMEM 映射一致 | 与既有内存映射方案对齐 |
| CN-08 | 所有 `int`、指针、数组元素 4 字节对齐；栈帧大小按 16 字节对齐 | 见 `AS-08`；ABI 要求 `sp` 16 字节对齐 |
| CN-09 | 函数参数个数上限为 8（`a0-a7`） | 超出即报"不支持"（`FR-509`），不实现压栈传参 |
| CN-10 | 编译器与运行时**不生成** `ecall`、CSR 指令、`URET`、`DIVU`、`REMU` | 避免牵扯异常/陷入处理；自研除法器不参与本链路 |
| CN-11 | 诊断信息使用英文，文档与注释使用中文 | 与 gcc/clang 惯例一致，便于对照与检索 |

### 3.3 外部依赖

| 编号 | 依赖 | 版本要求 | 用途 | 缺失后果 |
|---|---|---|---|---|
| DP-01 | `riscv64-unknown-elf-gcc`（含 binutils） | ≥ 12.2 | 提供 gas / ld / objdump / objcopy | 链路中断；`SC-01` 不可执行 |
| DP-02 | `qemu-riscv32` | ≥ 8.0 | 无硬件时的语义对照执行 | 失去与硬件解耦的验证能力（`AC-02`） |
| DP-03 | Python | ≥ 3.11 | 编译器实现与测试脚本运行环境 | 不可运行 |
| DP-04 | pytest + coverage.py | 最新稳定版 | 单元测试与覆盖率 | `AC-07` 不可验证 |
| DP-05 | 目标 CPU 的 `lui`、`sll`、`srl`、`sra` 实现 | — | 见 `AS-02` | 触发降级路径 `FR-109`（`RS-01`） |

### NFR-1xx｜性能

## 6. 外部接口需求

### IF-01｜命令行接口

```
mycc [options] <input.c>

选项：
  -o <path>            输出汇编文件路径（默认 a.s）
  --dump-tokens        打印 token 流到 stdout
  --dump-ast           打印带缩进的 AST 到 stdout
  --dump-ir            打印中间表示到 stdout
  --no-lui             禁止生成 lui，改用等价指令序列
  --no-vshift          禁止生成 sll/srl/sra，改用运行时函数
  --stats              在 stderr 打印各阶段耗时
  --version            打印版本与目标 ISA 标识
  -h, --help           打印帮助
```

**退出码**（遵循 `sysexits.h` 惯例）

| 码 | 含义 | 触发条件 |
|---|---|---|
| 0 | 成功 | 生成输出文件 |
| 1 | 源程序错误 | 词法/语法/语义错误，或使用了不支持的构造 |
| 2 | 编译器内部错误 | 断言失败或未捕获异常（`FR-704`） |
| 64 | 命令行用法错误 | 选项非法、缺少输入文件、多个输入文件 |
| 65 | 输入数据错误 | 源文件非 UTF-8 |
| 66 | 输入文件不可读 | 不存在、无权限、是目录 |
| 70 | 输出写入失败 | 目录不存在、无权限、磁盘满 |

**验收标准**：`mycc`（无参数）→ 64；`mycc a.c b.c` → 64；`mycc 不存在.c` → 66；`mycc -ioops a.c` → 64；`mycc -o /nonexistent/x.s 合法.c` → 70。四者均在 stderr 输出说明。

### IF-02｜输入：语言子集文法

完整文法见附录 A。要点：
- 编码：UTF-8（可含 BOM），换行 `\n` 或 `\r\n`
- 扩展名：`.c`（不强制，但不以 `.c` 结尾时给出警告）
- 最大规模：1000 行 / 128 KiB（超出报错，`FM-09`）
- 每个源文件必须包含且仅包含一个 `int main(void)` 定义（`FR-412`）

### IF-03｜输出：汇编文本格式

| 项 | 规定 |
|---|---|
| 语法 | GNU as（RISC-V）语法，目标体系 `riscv32` |
| 段 | 至少包含 `.section .text`，可选 `.section .rodata`、`.data`、`.bss` |
| 符号 | 每个全局函数与变量使用 `.globl <name>`；符号名按 C 标识符原样输出（不加下划线前缀） |
| 位置无关 | 不生成 PIC 相关重定位；不生成 `auipc` |
| 指令 | 机器指令严格属于 `IF-06`；允许使用 gas 伪指令（`li`/`la`/`mv`/`ret`/`j`），但其展开结果必须仍属白名单 |
| 调试信息 | 不生成 `.cfi` 指令（P0）；P2 可选 |
| 汇编兼容 | 必须能通过 `-mno-relax` 选项无警告汇编 |

### IF-04｜诊断信息格式

```
<file>:<line>:<col>: <severity>: <message>
<源行原文>
<spaces><caret>

[note: <附加说明，最多一条>]
```

实例（`SC-03`）：
```
demo.c:7:1: error: 'char' is not supported by this compiler (mycc supports 'int' only)
char c = 'A';
^~~~~
note: use 'int' instead; character literals such as 'A' are supported with type 'int'
```

- `severity` ∈ {`error`, `warning`, `note`}
- 列数为 1 基，按 Unicode 码位计
- 行长为 0 或行内含制表符时，caret 行按制表符宽度 4 展开
- 全部输出到 stderr（`FR-703`）

### IF-05｜运行时库 ABI

| 函数 | 签名 | 语义 | 是否可能被编译器自动生成调用 |
|---|---|---|---|
| `_start` | — | 初始化 `sp`、清零 `.bss`、`call main`、`a0` 传 `exit` | 否（由链接脚本指定入口） |
| `putchar` | `void putchar(int c)` | 低 8 位为字符，写串口 MMIO + VGA 文本缓冲区 | 否（仅显式调用） |
| `printint` | `void printint(int x)` | 十进制有符号输出，含负号 | 否 |
| `printhex` | `void printhex(int x)` | `0x` + 8 位十六进制 | 否 |
| `exit` | `void exit(int code)` | MMIO 输出状态码并自旋 | 否 |
| `__mulsi3` | `int __mulsi3(int a, int b)` | 32 位有符号乘法（低 32 位） | **是**（`FR-510`） |
| `__divsi3` | `int __divsi3(int a, int b)` | 有符号除法，向零取整；`b==0` 或 `INT_MIN/-1` 返回 `INT_MIN` | **是**（`FR-510`） |
| `__modsi3` | `int __modsi3(int a, int b)` | 有符号取余，符号同被除数 | **是**（`FR-510`） |
| `__ashlsi3` / `__lshrsi3` / `__ashrsi3` | `int f(int a, int n)` | 逻辑/算术移位，`n ≥ 32` 或 `n < 0` 时结果未定义 | 仅 `--no-vshift` 下（`FR-518`） |
| `memcpy` / `memset` | `void* memcpy(void*, const void*, unsigned)` / `void* memset(void*, int, unsigned)` | 提供但不由编译器自动生成（P0 无 `char`、无结构体赋值） | 否（P1 之后可能） |

**参数传递**：全部走 `a0`~`a7`，结果在 `a0`；不使用栈传参（`CN-09`）。

### IF-06｜目标 ISA 依赖清单（**最关键接口**）

**机器指令白名单（26 条）** —— 生成代码 + 运行时库的反汇编结果必须全部落在此集合内：

| 类别 | 指令 | 现状 |
|---|---|---|
| 寄存器算术/逻辑 | `add` `sub` `and` `or` `slt` `sltu` | **已有** |
| 寄存器移位 | `sll` `srl` `sra` | **需新增（3 条）** |
| 立即数算术/逻辑 | `addi` `andi` `ori` `xori` `slti` | **已有** |
| 立即数移位 | `slli` `srli` `srai` | **已有** |
| 高位立即数 | `lui` | **需新增（1 条）** |
| 访存 | `lw` `sw` `sb` | **已有** |
| 控制转移 | `beq` `bne` `blt` `jal` `jalr` | **已有** |

> **合计需新增 4 条指令：`lui`、`sll`、`srl`、`sra`。**

**明确不需要的指令及其替代方案**

| 不需要的指令 | 替代方案 | 依据 |
|---|---|---|
| `bge` `bgeu` `bltu` `sltiu` | `slt`/`sltu` + `beq`/`bne` 合成 | `FR-506` |
| `xor`（寄存器） | `(a\|b) - (a&b)` | `FR-515` |
| `lb` `lh` `lbu` `lhu` | P0 无 `char`/`short`，字符串以"每字符占 4 字节的 int 数组"表示 | §9.3 |
| `mul` `div` `rem` `mulh` 等 | 运行时库软件实现 | `FR-510`、`FR-606` |
| `auipc` | 非 PIC | `CN-06` |
| `ecall` `csrrw` 等 CSR 指令 `uret` `divu` `remu` | 输出走 MMIO；不使用异常/特权机制 | `CN-10` |
| `fence` `amo*` | 单核、无共享内存 | 单核假设 |

**越界检查**：`lint.sh`（`FR-609`）以本表为唯一判据，发现表外助记符即失败。

## 8. 优先级与迭代计划

### 8.1 优先级定义

| 级别 | 判据 | 缺失后果 |
|---|---|---|
| **P0（必须）** | 每次编译都会用到，或缺少它则链路断裂、无法演示、无法验证 | 课程设计不成立 |
| **P1（应当）** | 常见场景会用到，或用于风险兜底与质量提升 | 显著降低可用性/演示效果，但主体可交付 |
| **P2（可选）** | 罕见场景，或有更简单的替代做法 | 无实质影响 |

**优先级与频率的一致性校验**（课程评分项）：本文档中所有 P0 需求的"频率"列均为「每次 / 常见」，所有标为「罕见 / 仅风险期」的需求均为 P1 或 P2。唯一需要解释的是：

- `FR-109`（`--no-lui`/`--no-vshift`）频率为「仅风险期」却定为 P1：理由是它是 `RS-01` 的唯一缓解手段，且实现成本低（两条 lowering 规则），一旦硬件延期则升级为 P0。
- `NFR-104`（生成代码质量）为 P1 而非 P0：阈值有 3 倍余量，且不达标不影响链路的正确性。

### 8.2 迭代计划与 DoD

| 里程碑 | 交付内容 | DoD（定义完成） | 覆盖需求 |
|---|---|---|---|
| **M1** | 词法器 + 语法器 + AST + 诊断框架 | 附录 A 文法全部构造可解析；`--dump-tokens`/`--dump-ast` 可用；`FM-03`~`FM-06` 有测试；行覆盖率 ≥ 80% | `FR-2xx`、`FR-3xx`、`FR-7xx` |
| **M2** | 符号表 + 类型系统 + 语义分析 | 附录 A 全部类型规则实现；`FM-07`、`FM-08` 有测试；`FR-408`~`FR-414` 通过 | `FR-4xx` |
| **M3** | codegen + 运行时库 + 构建脚本 + lint + qemu 对照 | B1~B4 在 qemu 上输出正确；`lint.sh` 通过；`compare.sh` 与 GCC 结果一致；`FR-107`、`FR-511`、`FR-512` 通过 | `FR-5xx`、`FR-6xx`、`AC-02`、`AC-03` |
| **M4** | 游戏 B5 + 上板运行 + 覆盖率达标 + 文档 | B5 在开发板 VGA 上可交互运行 ≥10 分钟；`check.sh` 全绿；覆盖率达标 | `AC-04`、`AC-05`、`AC-07`、`FR-803` |
| **M5** | 缓冲与答辩准备 | `check.sh` 在干净环境可复现；追溯矩阵无空项；`NFR-301` 通过 | `AC-08`、`NFR-302` |

**M1~M3 为不可压缩路径**（`AC-01`~`AC-03` 的最小集）。M4 中的"上板"依赖 `DP-05`，若硬件未就绪则降级为"在 Logisim 中运行"并在验收报告中说明（`RS-01`）。

## 9. 范围边界

### 9.1 In Scope（P0，必须交付）

**语言构造**（附录 A 全量）：
- 类型：`int`、`int*`、`int[N]`、`void`（仅返回类型）
- 全局变量、全局数组（含 `{}` 常量初始化）
- 函数：`int`/`void` 返回，参数 ≤ 8 个，支持递归
- 语句：块、`if/else`、`while`、`for`、`return`、`break`、`continue`、表达式语句、块内声明
- 运算符：算术 `+ - * / %`、比较 `== != < <= > >=`、逻辑 `&& || !`、位运算 `& | ^ ~ << >>`、赋值与复合赋值、`++/--`、`[]`、函数调用、`sizeof`
- 字面量：十进制/十六进制/八进制整数、字符字面量（类型为 `int`）
- 注释：`//` 与 `/* */`

**工具与集成**：`mycc` CLI、`runtime.s`、`build.sh`、`lint.sh`、`compare.sh`、链接脚本、`check.sh`、测试与覆盖率报告。

### 9.2 Deferred（明确延后，编号保证可追溯）

| 特性 | 阶段 | 阻塞原因 |
|---|---|---|
| `?:` 三目、`switch/case`、`do-while` | P1 | 可被 `if`/`while` 等价改写，不阻塞目标应用 |
| 多错误恢复（`FR-108`）、`--stats`、`--no-lui`/`--no-vshift` | P1 | 质量与风险兜底 |
| `char` / `short` 类型、`char[]` 字符串字面量、`lb`/`lbu` | P1 | 需硬件 `lb`/`lbu`；P0 用"int 数组表示字符串"规避 |
| 一维以上的多维数组、`struct`、`union`、`enum`、`typedef` | P1/P2 | 类型系统复杂度陡增 |
| 类型转换 `(type)expr` | P1 | P0 的 int-only 子集中转换多为恒等 |
| 多文件编译与链接期重定位 | P2 | 目标应用单文件 |
| 常量强度削减（除法 / 取模）、窥孔优化 | P2 | 属优化范畴 |
| 最小预处理（`#define` 对象宏） | P2 | 目标应用可直接避免 |

### 9.3 Out of Scope（明确不做，含理由）

| 不做 | 理由 |
|---|---|
| 浮点（`float`/`double`） | 硬件无 FPU；软件浮点是一个独立项目 |
| 可变参数（`...`）与 `va_list` | 需要完整的栈传参机制，与 `CN-09` 冲突 |
| 函数指针、函数声明与定义分离的复杂情形 | 需要更复杂的类型系统与重定位 |
| 位域、`long long`、`unsigned` 类型族 | 与 `int`-only 子集不兼容；替代方案：显式用 `int` 并自行处理符号 |
| `goto` 与标签 | 会破坏结构化 codegen 的标签管理 |
| 逗号运算符 | 极少使用；已有块级表达式语句可替代 |
| 完整预处理器（`#include`/条件编译/宏函数） | `CN-05`；无 libc，运行时函数声明直接书写 |
| 标准库（`string.h`、`stdlib.h` 等） | 裸机环境；必要功能由 `runtime.s` 以最小接口提供 |
| 优化（内联、寄存器分配、循环优化、常量传播、公共子表达式消除） | `NG-02`；`FR-501` 已明确选择无优化路径 |
| 自举、跨平台后端（x86/ARM 目标） | `NG-03`；单一后端 |
| 自研汇编器与链接器 | `NG-04`、`CN-03` |
| 编译器图形界面 / IDE 集成 | RO-01~RO-03 均为命令行用户（§1.6） |
| 生成调试信息（`.cfi`/DWARF） | 目标平台无调试器 |
| 并发编译、增量编译 | 输入规模 ≤1000 行，无必要（`AS-04`） |

## 附录 A：C 子集文法

### A.1 顶层结构

```ebnf
program        ::= top_item* ;
top_item       ::= func_def | global_decl ;

func_def       ::= ( "int" | "void" ) IDENT "(" param_list? ")" "{" block_item* "}" ;
param_list     ::= param ( "," param )* ;              (* 个数 <= 8，见 CN-09 *)
param          ::= "int" IDENT ( "[" "]" )? ;

global_decl    ::= "int" IDENT ( "[" INT_LIT "]" )? ( "=" init )? ";" ;
init           ::= const_expr | "{" const_expr ( "," const_expr )* "}" ;
```

### A.2 语句

```ebnf
block_item     ::= stmt | local_decl ;
local_decl     ::= "int" IDENT ( "[" INT_LIT "]" )? ( "=" expr )? ";" ;

stmt           ::= compound | ";"
                 | "if" "(" expr ")" stmt ( "else" stmt )?
                 | "while" "(" expr ")" stmt
                 | "for" "(" expr? ";" expr? ";" expr? ")" stmt
                 | "return" expr? ";"
                 | "break" ";"
                 | "continue" ";"
                 | expr ";" ;
compound       ::= "{" block_item* "}" ;
```

### A.3 词法元素

| 类别 | 定义 |
|---|---|
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*`，长度 ≤ 255 |
| `INT_LIT` | `[0-9]+` \| `0[xX][0-9a-fA-F]+` \| `0[0-7]*`；值范围 0 ~ 4294967295（超出报错） |
| `CHAR_LIT` | `'`（单个字符 \| `\n` `\t` `\r` `\0` `\\` `\'` `\"`）`'` |
| 关键字 | `int` `void` `if` `else` `while` `for` `return` `break` `continue` `sizeof` |
| 运算符/分隔符 | `+ - * / % ++ -- = += -= *= /= %= == != < <= > >= && \|\| ! & \| ^ ~ << >> <<= >>= &= \|= ( ) [ ] { } ; ,` |
| 注释 | `//` 至行尾；`/*` 至 `*/`（不可嵌套） |

> 关键字表**故意不含** `char` `short` `long` `unsigned` `struct` `union` `enum` `typedef` `switch` `case` `default` `goto` `do` `double` `float` `const` `static` `extern` `volatile` `signed`。这些标识符被词法器识别为**保留但不受支持**的关键字，用于产出 `FR-409` 的专门诊断（而非被当作普通标识符，从而避免产生令人困惑的"未声明标识符"错误）。

### A.4 运算符优先级（由低到高）

| 级别 | 运算符 | 结合性 |
|---|---|---|
| 1 | `= += -= *= /= %= &= \|= <<= >>=` | 右 |
| 2 | `\|\|` | 左 |
| 3 | `&&` | 左 |
| 4 | `\|` | 左 |
| 5 | `^` | 左 |
| 6 | `&`（二元） | 左 |
| 7 | `== !=` | 左 |
| 8 | `< <= > >=` | 左 |
| 9 | `<< >>` | 左 |
| 10 | `+ -` | 左 |
| 11 | `* / %` | 左 |
| 12 | `+ - ! ~ * & ++ --`（前缀）、`sizeof` | 右 |
| 13 | `[] ()`（后缀）、`++ --`（后缀） | 左 |
| 14 | 字面量、标识符、`( expr )` | — |

解析方法：优先级爬升（precedence climbing），级别 12/13 由一元解析例程处理。

### A.5 语义规则要点

| 规则 | 说明 |
|---|---|
| 类型宽度 | `int`、`int*` 均为 4 字节 |
| 数组退化 | 数组名在表达式中退化为 `int*`，指向首元素 |
| 指针算术 | `int* + int` → 按 4 字节缩放；指针相减结果为 `int`（元素个数） |
| 下标 | `a[i]` ≡ `*(a + i)`；`a` 可为数组名或指针 |
| 比较 | 指针比较按无符号；`int` 比较按有符号 |
| 整数运算 | 无符号整型族不存在，所有运算按 32 位有符号补码，溢出为环绕（不报错） |
| 除法/取余 | 向零取整；`b == 0` 与 `INT_MIN / -1` 返回 `INT_MIN`（`FR-606`） |
| 布尔化 | 条件表达式的真值为"非零"；`&&` `\|\|` `!` 的结果为 `0` 或 `1` |
| 未初始化局部变量 | 值为未定义；编译器不做零初始化（全局变量在 `.bss` 中由 `_start` 清零） |
| 参数传递 | 值传递；`int` 与 `int*` 均占一个参数槽 |
| 返回 | `void` 函数不得 `return expr;`；`int` 函数必须 `return`，路径缺失为 P1 警告（`FR-413`） |

   - 属于 §9.2（Deferred）→ 变更优先级字段，不改变实现顺序，除非同时有不达标风险的缓解需求。
   - 其他 → 需在 `NFR-701` 的里程碑时间表内评估是否可容纳。
4. **同步**：受影响的需求条目、追溯矩阵（§11.2）、测试用例三者必须在同一次提交中一并更新。**任何一项缺失即视为变更未完成。**
5. **基线**：里程碑验收通过后，该版本需求文档冻结为基线；后续变更须显式说明与基线的差异。

**变更禁忌**：不得在没有新测试用例的情况下修改任何 P0 需求的验收标准（否则 `AC-01`~`AC-08` 失去意义）。
